# Обновление Git Time Machine до 0.8.1

Версия 0.8.1 исправляет смысловую агрегацию отчёта после появления функциональной кластеризации в 0.8.

## Что исправлено

### Документация больше не управляет выводами о продукте

`README.md`, `CHANGELOG.md`, `LOCAL_CHANGELOG.txt`, `AGENTS.md`, `ROADMAP.md` и другие документы анализируются только в кластере документации. Фразы внутри changelog больше не могут породить утверждения вида:

```text
Добавлено: личный кабинет
Удалено: личный кабинет
```

Факты о добавлении или удалении возможностей теперь должны подтверждаться изменениями исходного кода, SQL или конфигурации.

### Поддерживающие файлы не загрязняют чужие коммиты

Объединённый факт сначала разбивается по основным функциональным областям. Например, общий факт поиска, найденный одновременно в карточке ученика и форме договора, сохраняет в каждом кластере только собственные пути.

Исключение сделано для точных продуктовых SQL-фактов. Таблица `contract_contact_changes`, созданная в общем `includes/functions.php`, может подтвердить коммит договоров, но остальные факты из этого файла туда не переносятся.


### Общие utility-файлы фильтруются осторожнее

Для `includes/functions.php`, `learning-functions.php`, `bootstrap.php` и похожих общих файлов отключены слабые UI-эвристики вроде случайно найденных drag-and-drop, поиска или адаптивности. Точные функции, таблицы, поля БД и явно связанные продуктовые факты при этом сохраняются.

Факты `dev_environment_meta`, `database_pdo`, `ensure_dev_database` и связанные с ними функции направляются в основу приложения, а `contract_contact_changes` — в электронные договоры, даже когда они находятся в одном общем PHP-файле.

### Противоречия сворачиваются

Если одна и та же широкая возможность одновременно выглядит добавленной и удалённой в разных файлах, движок формирует один вывод `Изменено` и объединяет доказательства. Это безопаснее, чем показывать два взаимоисключающих пункта.

### Мелкие изменения объединяются

Кластеры с несколькими строками, без новых файлов и без значимых структурных фактов не получают отдельный коммит. Они объединяются в:

```text
Небольшие исправления
```

Например, небольшие правки форм заявок, отзывов и входа могут стать одним реконструированным коммитом.

### Технический шум перенесён из функционального описания

Отдельные пункты вида:

```text
GET current page
PAGE /admin/...
JSON response
redirect
```

больше не выводятся как продуктовые возможности. Они сворачиваются в одну структурную строку о технических обработчиках и точках взаимодействия.

### Названия коммитов описывают реальную возможность

Вместо общего:

```text
Обновлён функциональный блок «Ученики и успеваемость»
```

движок может сформировать:

```text
Добавлены редактирование контактов и график успеваемости ученика
```

Также добавлены отдельные шаблоны для dev-базы, истории изменения контактов договора, международного телефона, календаря админки, календаря личного кабинета и создания расписания из карточки ученика.

## Проверка

```powershell
npm run test:core
npm run build
```

Smoke-тест дополнительно проверяет:

- изоляцию документации;
- отсутствие чужих путей в фактах кластера;
- объединение мелких изменений;
- устранение конфликтующих add/remove-выводов;
- формирование функциональных названий коммитов.

## Коммит для Git

```powershell
git add .
git commit -m "fix: refine functional commit aggregation"
git push origin main
```
